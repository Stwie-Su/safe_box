## 1. 产品定位

多用户共享保险柜。目标场景是民宿短租、小型办公室、成员多且需要权限分级的家庭。

这类场景下，多用户权限、TOTP 二次验证、远程管理、审计日志、限时授权都是必需项。
如果按"家庭保险柜"定位，这四项会变成低频场景下的过度设计。

## 2. 用户模型

### 2.1 角色与权限

| 角色 | 字段值 | 典型身份 | 权限 |
|---|---|---|---|
| 管理员 | `admin` | 房东、老板、户主 | 全部权限：三通道开锁、用户增删改、切换各通道有效性、修改置信度阈值、查看/导出日志、发放临时授权 |
| 长期用户 | `user` | 家庭成员、员工、长租客 | 三通道开锁、查看自己的开锁记录 |
| 临时用户 | `temp` | 短租客、访客、家政 | 按管理员指定通道开锁，限时（到期自动失效）+ 限次（次数用尽失效） |

### 2.2 硬约束

1. 删除用户后必须仍保留至少 1 个启用状态的管理员，防止系统被锁死。
2. 临时用户到期或次数用尽后自动置为停用，**不删除记录**，保留审计线索。
3. PIN 只存 PBKDF2-SHA256 哈希 + 每用户随机盐，不存明文，不做可逆加密。
4. 敏感操作（增删用户、切换通道开关、修改阈值、远程开锁）执行前需管理员 TOTP 二次确认。

## 3. 功能需求

### FR-1 开锁认证（三通道共用一张用户表）

| 通道 | 校验逻辑 | 本期状态 |
|---|---|---|
| 静态 PIN | 输入 PIN → 匹配用户 PIN 哈希 → 检查用户启用态与有效期 | 已有，迁入新结构 |
| 人脸识别 | 人脸结果 `{face_id, score}` → 映射用户 → 检查 `face_enable` → 按分数分级 | 接口预留 + 模拟后端 |
| 动态密码 | 输入 6 位码 → 用该用户 `totp_secret` 做 RFC 6238 校验 → 检查 `totp_enable` | 已有，迁入新结构 |
| 远程 RPC 开锁 | MQTT `remote_unlock`，带合法 otp 直接开；不带则触发本地动态码弹窗 | 已有，迁入新结构 |

三个通道共用同一张用户表，统一由 `app/core/auth` 编排。

### FR-2 人脸置信度分级状态机

| 分数区间 | 动作 |
|---|---|
| `score >= 85` | 直接开锁：驱动执行器、写日志、MQTT 上报 |
| `60 <= score < 85` | 进入 WAIT_OTP，TOTP 通过后开锁（60s 超时算失败） |
| `score < 60` | 直接拒绝，写失败日志 |
| 分数越界（<0 或 >100） | 视为无效输入，不触发状态迁移 |

阈值 `score_high` / `score_mid` 存在 `users.json` 的 policy 段，可由管理员通过界面或 RPC 修改。

状态与超时：

| 状态 | 含义 | 超时 |
|---|---|---|
| IDLE | 待机 | — |
| DETECTING | 识别中 | 5s 无结果回 IDLE |
| UNLOCKED | 已开锁 | 3s 后回 IDLE |
| WAIT_OTP | 等待动态码 | 60s 超时算失败 |
| DENY | 拒绝 | 2s 后回 IDLE |
| LOCKOUT | 锁定 | 30s 后回 IDLE 并清零计数 |

### FR-3 敏感操作二次确认

以下操作不直接执行，先要求管理员 TOTP 动态码：增删用户、切换人脸/PIN/动态码开关、修改置信度阈值、远程开锁。

### FR-4 失败锁定

1. 连续 5 次失败（识别失败或动态码错误）→ 锁定 30s，界面显示倒计时。
2. 计数与锁定**按用户维度**（ADR-3），避免一个用户被攻击导致其他人开不了锁。
3. 同时维护全局失败计数用于告警，但全局计数不触发锁定。

### FR-5 远程监控与 RPC

MQTT 四个主题：

| Topic | 方向 | 说明 | QoS |
|---|---|---|---|
| `safe/status` | 设备 → 手机 | 周期上报（5s）+ 状态变化时立即上报 | 0 |
| `safe/log` | 设备 → 手机 | 操作/告警日志、指令回执 | 1 |
| `safe/cmd` | 手机 → 设备 | RPC 指令 | 1 |
| `safe/config` | 手机 → 设备 | 阈值、用户等配置下发 | 1 |

指令集：`query_status` / `remote_unlock` / `add_user` / `del_user` / `set_face_enable` /
`set_threshold` / `sync_time` / `inject_score`（仅调试）。
回执统一发 `safe/log` 并带 `req_id`，错误码见上游文档 2.6。

### FR-6 时间基准

TOTP 依赖准确时间，抽象为 `hal_time`：

- 未装 DS3231 前返回系统时间，PC 上可完整验证 TOTP 逻辑；
- 装后改为读 RTC，并支持 MQTT `sync_time` 校时。

### FR-7 视频预览

抓 MJPEG 流 → 解码 → RGB565 → LVGL Canvas，分辨率锁 320×240。
本期只留 `hal_camera` 接口与空实现，不实现解码链路。

### FR-8 执行器控制

GPIO 驱动继电器 → 电磁锁。先 LED 模拟，确认逻辑后再接真实电磁锁。
动作时长硬性上限 500ms，超时强制关闭（NFR-7）。

### FR-9 临时授权

管理员可为临时用户指定有效期（起止时间戳）、次数上限、可用通道。
到期或次数用尽自动停用，不删除记录。

### FR-10 物理安全告警（P2，有余力再做）

防撬震动报警、胁迫密码、异常时段告警。本期只留事件类型枚举与日志接口，不实现检测逻辑。

## 4. 非功能需求

| 编号 | 项目 | 指标 |
|---|---|---|
| NFR-1 | 离线可用 | 人脸 + 动态码 + 开锁不依赖外网 |
| NFR-2 | MQTT 延迟 | 局域网内指令到执行 < 500ms |
| NFR-3 | 动态密码 | RFC 6238，30s 窗口，±1 窗口容忍，一码一用（防重放） |
| NFR-4 | 失败锁定 | 连续 5 次失败锁定 30s |
| NFR-5 | 可移植性 | PC 与板子共用同一套业务代码，差异只落在 HAL 与平台引导层 |
| NFR-6 | 稳定性 | MQTT 断线自动重连；板子上开机自启 |
| NFR-7 | 执行器安全 | 继电器动作时长上限 500ms，超时强制关闭 |

## 5. 本期范围

### 5.1 做

1. 工程骨架重构：目录分层、构建模块化、统一错误码与事件总线。
2. 人脸识别模块接口预留：异步接口 + 后端注册机制，先给模拟后端，FM225 后端留空壳。
3. 现有业务逻辑迁入新结构，PC 上功能不回退。
4. PC 端单元测试骨架：置信度边界、TOTP 窗口与防重放、失败锁定。
5. PC 构建与板子交叉构建两条链路都保持可用。

### 5.2 不做

| 不做项 | 理由 |
|---|---|
| 真实人脸采集与 UART 协议解析 | FM225 未到货，只留接口与后端空壳 |
| DS3231 驱动 | 硬件未购，时间源先用系统时间 |
| 视频预览解码链路 | 依赖 FM225 的 USB 视频流 |
| 公网穿透 / 云服务器 / 域名备案 | 面试非必需 |
| 微信小程序 | MQTTX 已足够演示远程闭环 |
| 指纹 / NFC / 4G / CAN | 分散精力 |
| 数据库替代 JSON 存储 | 数据量为个位数用户 + 千条日志，抽象层已保证后续可换 |

## 6. 验收标准

### 6.1 工程结构

| # | 检查项 | 期望 |
|---|---|---|
| 1 | PC 构建 | `cmake -B build_pc -DLV_PORT_DEFCONFIG=configs/pc.defconfig . && cmake --build build_pc` 无错误无新增告警 |
| 2 | 板子交叉构建配置 | 配置阶段不因缺 PC 端依赖而失败 |
| 3 | 关闭 MQTT 特性 | 工程仍可编译运行，相关调用降级为空实现 |
| 4 | 单元测试 | `ctest --test-dir build_pc` 全部通过 |
| 5 | 分层检查 | `app/core` 下不出现 LVGL 头文件与平台头文件（`grep` 可验证） |
| 6 | 运行时数据 | 不再写入源码目录，落在独立数据目录 |

### 6.2 功能闭环（PC）

| # | 操作 | 期望 |
|---|---|---|
| 1 | 发 `query_status` | 收到状态回执 |
| 2 | 注入 score=90 | 直接开锁，日志有 UNLOCK 事件 |
| 3 | 注入 score=75 | 弹动态密码页，输入正确 TOTP 后开锁 |
| 4 | 注入 score=50 | 直接拒绝，日志有 DENY 事件 |
| 5 | 连续 5 次失败 | 进入 LOCKOUT，界面倒计时 30s |
| 6 | 订阅 `safe/log` | 完整事件流可见 |

### 6.3 用例边界

见 `docs/04-测试计划.md`，覆盖置信度边界值、TOTP 窗口与防重放、失败锁定、MQTT 回执。
