## 2. UI 目录结构与外壳（2026-08-31 重构）

`app/ui/` 是视图层，只做「界面渲染 + 事件绑定」；业务判定走 `app/core/`，硬件动作走 `app/hal/`。

| 文件 | 职责 |
|---|---|
| `ui/ui.h` | 页面枚举 `ui_page_t`、页面切换接口；信息架构（主页/用户/日志/设置 四页签） |
| `ui/ui.c` | **外壳框架**：56px 顶栏（锁状态点 + 时钟 + MQTT 连接点）+ 72px 四胶囊页签（主页/用户/日志/设置）+ 内容容器；`tab_index_of()` 路由；`fsm_ui_hook` 桥接状态机→页面切换 |
| `ui/theme.h` | 12 色角色枚举 `theme_role_t`、4 套色板 `THEMES[4]`、全局 `lv_style_t` 复用样式、主题切换 API |
| `ui/theme.c` | 四套精确色板（石墨黑/月白/蓝白/松石青）+ 全局样式初始化 + `theme_switch()` 一键换肤 |
| `ui/ui_scale.h/.c` | 1024×600 设计基准 → 运行时自适应缩放 `SX()/SY()`、中文 FreeType 字体 `app_font_scaled()` |
| `ui/pages/page_monitor.c` | 主页：锁状态圆环 + 状态标题 + 双开锁方式 + 三联信息卡 |
| `ui/pages/page_users.c` | 用户管理（底部「用户」一级页签；**改管理员密码走动态码二次确认**，删除走 admin PIN） |
| `ui/pages/page_logs.c` | 日志（一级页签） |
| `ui/pages/page_settings.c` | 设置中枢（admin PIN 二次验证）→ 网络/系统入口 |
| `ui/pages/page_system.c` / `page_network.c` | 系统/网络 子页 |
| `ui/pages/page_keypad.c` / `page_otp.c` | 全屏覆盖层：PIN 键盘 / 动态码确认（人脸开锁双因子） |
| `app/platform/debug_hooks.c` | PC 调试钩子：`SAFE_TEST_DLG=add_user/auth/change_pwd/otp` 直接打开对应弹窗截图 |

**外壳尺寸（设计基准，运行时 ×scale）**

| 区域 | 高度 | 内容 |
|---|---|---|
| 顶栏 TopBar | 56px | 左：锁状态点+文本胶囊；中：实时时钟；右：MQTT 连接点 + WiFi |
| 内容区 | `h - 56 - 72` | 各页面在此创建（显隐切换，不重建） |
| 底栏 TabBar | 72px | 四枚等宽胶囊页签：主页 / 用户 / 日志 / 设置 |

**主题系统要点**
- 颜色集中：`THEMES[4]` 四套色板，页面控件只引用 `lv_style_t` 或 `theme_color(role)`，绝不写死 hex。
- 切主题：`theme_switch(idx)` 更新样式内容后 `lv_obj_report_style_change(NULL)` 全局刷新，页面无需重建即可换肤。
- 顶栏本地颜色覆盖（锁点/MQTT 点/时钟）通过 `theme_register_change_cb()` 在换主题时同步刷新。
- **默认主题：月白（index 1，浅色暖色）**。

## 7. 总体分层（架构设计）

系统采用「业务核心 / 硬件抽象 / 视图 / 平台」四层分离，依赖方向单向向下，视图层（UI）与硬件层（HAL）均不直接耦合业务判定，便于 PC 验证与板子上板双构建。

```
┌──────────────────────────────────────────────────────────────┐
│                        app/ui  (LVGL 视图层)                    │
│   外壳(ui.c) · 页面(pages/) · 主题(theme.c) · 字体(ui_scale)    │
└───────────────▲───────────────────────────────▲──────────────┘
                │ 事件回调                          │ 状态查询/订阅
┌───────────────┴──────────┐        ┌─────────────┴──────────────┐
│   app/core  (业务核心)     │        │   app/hal  (硬件抽象层)      │
│ auth / store / remote /    │        │ actuator / camera / face /   │
│ support / config / event   │        │ time  （backend 可注册）     │
└───────────────▲──────────┘        └─────────────▲──────────────┘
                │                                   │
┌───────────────┴───────────────────────────────────┴──────────────┐
│              app/platform  (平台适配：SDL / FBDEV / null / debug)   │
└───────────────────────────────────────────────────────────────────┘
```

**依赖纪律**
- `ui/` 只做渲染与事件绑定，业务判定一律走 `core/`，硬件动作一律走 `hal/`。
- `core/` 不 `#include` `ui/` 与 `hal/` 具体后端，仅通过 `hal_*` 接口与 `auth_fsm` 等 API 交互。
- `hal/` 通过统一 `backend.h` 注册机制，运行时按平台选择 mock / 真实后端。

## 8. UI 外壳架构（架构设计）

外壳由 `ui.c` 一次性构建，页面以「显隐切换」方式常驻内存，切换不重建（避免重建开销与主题漂移）。

```
lv_screen_active()
 ├─ TopBar  (56px)  ：锁状态点 + 文本胶囊 | 实时时钟 | MQTT 连接点 + WiFi
 ├─ Content  (h-56-72)：s_content 容器，承载 8 个页面根节点（s_page_roots[]）
 └─ TabBar  (72px)  ：4 胶囊页签 → s_tab_btns[0..3]
```

**页面枚举与路由**（`ui_page_t`）

| 页面 | 一级页签 | 说明 |
|---|---|---|
| `PAGE_HOME` | 主页 | 锁状态圆环 + 双开锁方式 + 三联信息卡 |
| `PAGE_USERS` | 用户 | 用户管理（改管理员密码走动态码，删除走 admin PIN） |
| `PAGE_LOGS` | 日志 | 审计日志列表 |
| `PAGE_SETTINGS` | 设置 | 设置中枢（admin PIN 二次验证） |
| `PAGE_NETWORK` / `PAGE_SYSTEM` | （设置子页） | 网络 / 系统 子页 |
| `PAGE_KEYPAD` / `PAGE_OTP` | （全屏覆盖层） | PIN 键盘 / 动态码确认，`tab_index_of()` 返回 -1 不切高亮 |

路由函数：
- `tab_index_of(page)`：返回页面所属页签索引；覆盖层返回 `-1`（保持当前高亮）。
- `switch_page(page)`：更新页签 `CHECKED` 状态 + 显隐 `s_page_roots[]`。
- `TAB_PAGES[4]`：页签点击 → 目标页面映射 `{HOME, USERS, LOGS, SETTINGS}`。

## 10. 认证状态机（auth_fsm）

置信度三档 + 防暴锁定，是 UI 与业务的解耦枢纽。

```
        detect(score)
   IDLE ─────────────► DETECTING ──score≥high──► UNLOCKED ─┐
                         │                                  │
                         │ score∈[mid,high)                 │ (开锁)
                         └────────────► WAIT_OTP ─submit───► │
                         │ score<mid                         │
                         └────────────► DENY                  │
                                                          (回到 HOME)
   任意态：连续失败 max_failed=5 ─► LOCKOUT(30s) ─倒计时─► IDLE
```

- `auth_fsm_set_ui_hook()`：状态变化 → `fsm_ui_hook()` 桥接页面切换（WAIT_OTP→OTP 页，UNLOCKED/LOCKOUT→主页）。
- UI 不直接调用 LVGL 业务动作，全部经 `auth_fsm_*` API，符合「视图层不碰业务判定」纪律。

## 11. 数据持久化（store + credentials）

- 用户库 `users.json`、审计日志 `safe.log`（JSON Lines）位于 `data/`，**不入库**。
- 统一抽象存储层，PIN 仅存 PBKDF2-SHA256 哈希 + 每用户随机盐，无明文。
- 后台线程 `worker.c` 投递重活（统计/校验），结果回主线程回调，避免阻塞渲染（NFR-性能）。

---

## 12. 远程通道（rpc + mqtt_client）

- MQTT 客户端连接局域网 Broker，`rpc.c` 主线程消费指令队列（线程安全）。
- 支持指令：`inject_score` / `query_status` / `remote_unlock` / `submit_otp`（调试）。
- 敏感操作（远程开锁/增删用户/改阈值）强制携带管理员 TOTP（FR-3），缺 otp 回 2001。
- 事件经 `safe/log` 主题上送（UNLOCK/DENY/LOCKOUT）。
- 顶栏 MQTT 连接点由 `mqtt_is_connected()` 驱动（绿=在线 / 红=离线）。

## 14. 设计约束（NFR 落地）

- **离线优先**：认证链路不依赖外网；远程仅局域网。
- **安全**：PIN 仅存哈希、连续失败锁定、敏感操作二次验证、审计可追溯。
- **可测试**：状态机可脚本化断言；headless（Xvfb+SDL+mosquitto）MQTT 验收。
- **主题一致**：禁止硬编码颜色；换主题全局刷新，页面不重建。默认主题=月白。
