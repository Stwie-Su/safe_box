## 1. 项目定位与场景

基于 i.MX6ULL 的**多用户共享保险柜系统**，面向民宿/短租、小型办公室、多成员家庭等「多人共用同一柜体」场景。

核心认证链路为 **人脸识别（FM225 双目活体模组）或 PIN 开锁**；**TOTP 动态密码**承担敏感操作二次确认与暴力破解应对，并作为人脸 / PIN 不可用时的备用认证通道。配套本地界面、远程监控与远程指令，以及**限时/限次的临时授权**（房客退房到期自动删除用户）。

基本约束：

- **离线优先**：认证链路不依赖外网，断网仍可正常开锁。
- **局域网远程**：仅局域网内可查看状态、下发开锁与管理指令。
- **硬件受限**：imx6ull,单核 Cortex-A7，一切性能设计以此为前提。
- **人脸模组约束**：FM225 识别距离 30~120cm、识别角度约 ±20°、人脸容量 100 人；录入与验证交互、结构安装均按此约束设计。

## 2. 术语与优先级定义

| 术语 | 含义 |
|---|---|
| 活体检测 | 由人脸模组执行，判断镜头前是真人而非照片 / 视频的防伪检测 |
| 未匹配 | 活体通过，但未命中任何已注册人脸 |
| 防伪告警 | 活体检测失败（疑似照片 / 视频攻击）触发的事件 |
| 动态码 OTP | 基于时间的一次性密码（TOTP），6 位 |
| 临时授权 | 限时（有效期）与限次（次数上限）的授权，到期或用量耗尽自动**删除用户** |
| 敏感操作 | 增删改用户、人脸录入与删除、修改阈值、切换认证通道、远程开锁 |

优先级定义：

| 级别 | 含义 |
|---|---|
| P0 | 不做则项目不成立 |
| P1 | 核心亮点，直接影响项目价值与简历含金量 |
| P2 | 有则加分，无则不影响主线 |

## 5. 业务流程需求

### 5.1 人脸开锁判定（FR-2、FR-19、FR-20）

人脸模组仅返回「成功 / 失败（含原因码）」，**不输出比对分数**，系统按失败原因分流：

| 模组结果 | 系统行为 |
|---|---|
| 验证成功（活体通过且命中注册人脸） | 核对本地凭据与用户状态：启用且未锁定 → 直接开锁；已停用 / 已锁定 / 凭据失效 → 拒绝 |
| 验证失败·未匹配（活体通过但非注册用户） | 拒绝并计入失败；**连续未匹配达 `face_otp_after`（默认 3）→ 强制动态码验证身份**；继续失败达 `max_failed` → 设备级锁定（FR-4） |
| 验证失败·活体检测失败 | 拒绝并计入失败，同时触发防伪告警（FR-10，即时上报 R-2） |
| 超时 / 未检出人脸 | 回到待机并提示，**不计入失败** |

附加行为需求：

- 人脸验证超时默认 10s，管理员可配置（上限 255s）。
- 人脸验证进行中允许切换为 PIN 输入（打断当前验证）。
- 已处于动态码验证态时，同一用户人脸验证成功应直接开锁（升级路径），不强制走动态码。
- 开锁成功后展示结果若干秒（默认 3s）再回到待机；拒绝展示约 2s。
- **职责边界**：模组只承担认证，开锁动作统一由系统执行器执行（受 NFR-3 脉冲上限约束）。

### 5.2 PIN 开锁（FR-1）

- 输入 PIN 后匹配任一**启用且未锁定**的用户，成功即开锁。
- PIN 长度 4–8 位，可配置最短/最长。
- **虚位密码（FR-18）**：允许在正确 PIN 的前后附加任意数字，只要输入串中**连续包含**正确 PIN 即判定通过，用于防止旁人窥视。
  - 最大输入长度 20 位。
  - 仅适用于**开锁 PIN 通道**；管理员二次确认与动态码不适用（见 5.5）。
  - 该功能可由管理员开关控制。

### 5.3 防暴力锁定（FR-4）

- PIN 失败与人脸未匹配**合并计入同一失败计数**，成功开锁清零。
- 连续失败达 `max_failed`（默认 5）次进入设备级锁定，持续 `lock_seconds`（默认 30s）。
- **锁定期间拒绝一切开锁请求**，包括管理员的远程开锁指令（返回「系统锁定」错误）。
- 锁定判定优先于任何凭据校验：不得出现「锁定期间仅凭动态码即可开锁」的路径。

### 5.4 动态码（FR-3）

- 6 位数字，基于时间片（默认 30s）生成。
- 容忍前后各一个时间片的时钟偏差。
- **一码一用**：同一时间片内同一码只能成功使用一次，重复提交判为重放并拒绝。
- 动态码通道可由管理员选择是否启用。
- 如果检测到暴力破解：需要动态码验证身份（触发条件见 5.1 分流）。

### 5.5 敏感操作二次确认（FR-14、FR-1）

| 操作 | 二次确认方式 |
|---|---|
| 修改**管理员**密码 | 强制动态码 |
| 修改普通用户密码 | 校验旧 PIN 即可 |
| 删除用户 | 管理员 PIN |
| **人脸录入 / 删除人脸** | 管理员 PIN |
| 进入设置中枢 | 管理员 PIN |
| 远程开锁 / 增删用户 / 改阈值 | 强制管理员动态码 |

**虚位密码的适用边界**：虚位为防窥视而设计，代价是削弱暴力破解难度（一次 20 位输入相当于同时试多个候选）。因此：

- 开锁 PIN：**支持**虚位，依赖失败锁定（FR-4）对冲破解成本。
- 管理员二次确认：**不支持**虚位，必须精确匹配——敏感操作不允许以降低精度换取便利。
- 动态码：不适用，动态码为定长 6 位且一码一用。
- 如果检测到暴力破解：需要动态码验证身份。

### 5.6 临时授权（FR-9）

- 管理员可设置有效期截止时间与开锁次数上限。
- **到期或次数耗尽后，系统自动删除该用户信息（含其人脸凭据等全部数据），无需人工回收**；删除动作记入审计日志。
- 删除后该用户全部凭据自然失效；对模组侧人脸按 FR-21 联动删除，模组删除失败时以本地凭据失效标记兜底。

## 6. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-1 | 离线优先 | 认证链路不依赖外网；远程能力暂时仅限局域网 |
| NFR-2 | 安全 | PIN 仅存哈希（每用户随机盐），明文不落盘；敏感操作二次验证；操作可追溯 |
| NFR-3 | 性能 | 目标单核 A7；视频预览时界面保持流畅不卡顿；开锁脉冲受硬件约束（执行器高脉冲 ≤400ms,否则会烧坏） |
| NFR-4 | 可靠 | 配置写入需防掉电损坏；断网期间事件不丢失，恢复后补传；异常退出可自动恢复；日志需限额滚动，不得撑满存储 |
| NFR-5 | 可维护 | 分层单向依赖；配置、主题、错误码集中管理；新增硬件能力不改动业务代码；后续新增OTA |
| NFR-6 | 可移植 | 同一份业务源码可在 PC 与目标板两种平台构建 |
| NFR-7 | 可测试 | 支持无头环境（虚拟显示 + 模拟后端 + 本地消息代理）完成端到端自动化验收 |
| NFR-8 | 外观一致性 | 界面取色统一走主题，禁止硬编码颜色值；换主题无需重建页面 |

## 7. 数据需求

| 数据 | 内容 | 要求 |
|---|---|---|
| 用户 | ID、名称、角色、PIN 哈希与盐、启停状态、失败计数、锁定截止、动态码密钥、通道开关、临时授权字段 | PIN 仅存哈希；动态码密钥加密或受控存储 |
| 人脸凭据 | 见 7.1 | 每用户 0 或 1 条；失效后即使模组返回成功也拒绝 |
| 安全策略 | PIN 长度范围、失败阈值、锁定时长、连续未匹配转动态码阈值（`face_otp_after`）、人脸验证超时 | 可配置并持久化 |
| 审计日志 | 时间、事件类型、用户、成败、详情（人脸事件含失败原因码与模组侧 ID） | 逐条追加；保留条数上限，超出滚动 |
| 网络凭据 | WiFi SSID / 加密方式 / PSK | 可逆加密存储，不以明文落盘 |
| 设备密钥 | 设备级密钥 | PC 阶段可用固定串，上板阶段需替换为真实密钥 |

### 7.1 用户与人脸凭据模型

| 概念 | 内容 |
|---|---|
| 系统用户档案（唯一身份源） | ID、名称、角色、PIN 哈希与盐、启停状态、失败计数、锁定截止、动态码密钥、通道开关、临时授权字段 |
| 人脸凭据（可选凭据） | 归属用户 ID、模组侧用户 ID（句柄）、已录入方向集合、录入时间、状态（有效 / 失效） |

规则：

- 用户 : 人脸凭据 = **1 : 0..1**；未录入人脸的用户不存在凭据对象，不占位、不预分配。
- 身份与角色永远以系统档案为准；模组只回答「这张脸对应模组侧几号」，系统再查该号码绑定的用户与状态。
- 用户名冗余写入模组用于对账，用户名长度受模组 32 字节限制。
- 模组侧 ID 会被复用，人脸凭据的有效性以系统侧标记为准。
- 删除用户 / 到期删除 / 恢复出厂 → 按 FR-21 联动处理人脸凭据。

| 项 | 理由 |
|---|---|
| 照片注册 | 照片可被冒用，与保险柜安全定位冲突；仅支持现场活体录入 |
| 演示模式用于生产 | 模组演示模式不做比对、人人可过，仅限开发调试使用 |
| 模组执行开锁 | 开锁统一由系统执行器执行（见 5.1 职责边界） |
| 置信度分数相关功能 | 模组不输出分数，相关需求已整体移除 |

## 10. 验收标准

分层验收，每层可独立复现。

| 层级 | 范围 | 通过标准 |
|---|---|---|
| 单元 | 认证状态机、动态码、存储 | 全部用例通过 |
| 单元 | 虚位密码匹配 | 前后加扰的长串可通过；不含正确 PIN 的长串被拒；管理员二次确认不接受虚位 |
| 单元 | 人脸凭据模型与一致性 | 未录脸用户不占位；删用户联动删凭据；凭据失效时即使模组返回成功也被拒 |
| 集成 | 无头环境端到端（远程指令驱动开锁/拒绝/锁定） | 全部用例通过，锁定期间无误触发 |
| 集成 | 人脸判定分流 | 成功开锁；未匹配连续达阈值转动态码；活体失败触发防伪告警；超时 / 无人脸不计失败 |
| 人脸录入 | 多方向交互录入 | 引导与已录方向进度显示正确；取消后录入状态清零；容量满（100）提示明确 |
| 目标板 | 显示、触摸、中文、防息屏、稳定运行 | 交互正常，长时间运行不退出 |
| 目标板 | 人脸模组稳定性 | 模组故障时系统降级不崩溃、告警可见，恢复后自动回归正常认证 |
| 视频预览 | 实时画面小窗 | 画面连续，界面操作不卡顿 |
| 手机端 | 标准 MQTT 客户端订阅与下发 | 状态可见、指令有回执 |

**手机端最小验收闭环**：设备运行 → 手机连接同一局域网 → 订阅全部设备主题 → 下发状态查询指令 → 在超时前收到状态回执，且回执中显示连接在线。
