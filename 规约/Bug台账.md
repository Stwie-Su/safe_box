# Bug 台账

> **本文件是「每次任务后必更新」的文档。** 修了任何缺陷——**包括自己这次引入的回归**——都要来加一行。
> 一行一条，四列齐全（现象 / 根因 / 解法 / 教训）；完整叙事见 `案例/Debug案例集_整理版.md`。
>
> **编号规则**：`D##` 全局递增，**不复用、不重排**（另有少量 `QA-##` 为早期编号，保留原样）。
> ⚠ **新增前必做**：`grep -rn '^| D' Bug台账.md | tail -20` 确认下一个可用编号 —— 本项目撞号撞过两次。
> 当前已用到 **D32**，下一个是 **D33**。

## 更新规则（写清楚才不会漏）

| 什么时候 | 记什么 |
|---|---|
| 修了一个缺陷 | 一行四列；**教训列必须写**——写不出教训说明根因还没挖透 |
| 本次改造引入了回归 | 照记，不遮掩。编号照领，来源注明「本次改造引入」 |
| 排查很久才发现不是 bug | 记进「环境 / 链路层」——这类最占时间，不记下次还会再查一遍 |
| 加了一道门禁 / 扫描器 | 记为一条，注明它拦的是什么（防止后人觉得多余而删掉） |

## 附录 A：分层排查速查

断言链：**ping → TCP → TLS → 应用回执 → 业务关联 → UI 呈现**，每层一条 yes/no 断言，
第一条失败的就是分界点。探针命令与反模式见 `案例/排错方法论_二分定位.md`。

三条最常复用的铁律：

1. **先取证再动手** —— 改两次没效果就插桩量数据（几何 / 计数 / errno），别继续猜；
2. **两端日志 + 中间链路** —— 跨机问题必须同时拿对端视角，否则互相甩锅；
3. **PC 通过不代表板端通过** —— 2x 缩放会掩盖绝对像素类 bug，上板后必须重验布局。
