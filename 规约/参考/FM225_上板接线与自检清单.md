# FM225（FM22x 双目人脸模组）上板接线与自检清单

> 适用：i.MX6ULL（100ask）板 + 本工程 `lv_port_linux`
> 编写日期：2026-09-12　编写人：software-engineer
> 状态：**模组与 DS3231 均尚未到货**，本文档是到货前的预备工作（串口可配置化 + 自检工具 + 接线/排查口径）。
> 凡标注「**板上实测**」的条目，均已在真机 `/dev/ttymxc2` 上跑过；未标注者为待到货后确认。

## 1. 板上已有资源（板上实测）

| 资源 | 节点 | 说明 |
|---|---|---|
| UART3（**FM225 目标口**） | `/dev/ttymxc2` | `crw-rw---- root:dialout`，存在且可 open、termios 115200 配置成功 |
| UART1（调试串口） | `/dev/ttymxc0` | 已被 console 占用，**不要拿来接模组** |
| UART6 | `/dev/ttymxc5` | 备用 |
| I2C 总线（DS3231 目标） | `/dev/i2c-0`、`/dev/i2c-1` | 挂 DS3231 用；具体哪一路以原理图为准 |
| RTC | `/dev/rtc0` | **片上 SNVS**，`snvs_rtc` 驱动；`dmesg` 有 `setting system clock to 1970-01-01` |

**关键事实（板上实测，决定了为什么必须外接 DS3231）**：
板上 `date -u +%s` == `uptime` 换算的秒数（实测 `8216` ≈ 2h16m），即**每次上电系统时钟从 0 开始**——
SNVS `rtc0` 没有备份电池，不能作为持久化时间源。TOTP / 日志时间戳 / 状态上报在断电后全部失效，
必须外接 DS3231（备份电池）后导出 `/dev/rtc1` 并使用本工程 `SAFE_TIME_BACKEND=rtc`。

## 2. 接线

### 2.1 UART（FM225 ↔ 板）

| 信号 | 模组侧 | 板侧 |
|---|---|---|
| TXD | 模组 TX | 板 **RX** |
| RXD | 模组 RX | 板 **TX** |
| GND | GND | GND（**必须共地**，否则收到乱码） |
| VCC | 按模组规格书 | 底板 5V 或 3.3V 排针 |

- **TX/RX 必须交叉**（模组 TX 接上位机 RX）。这是上板最常见的接错点。
- **电平**：i.MX6ULL 的 UART 是 **3.3V TTL**。若模组是 5V TTL 或 RS232 电平，**必须加电平转换**，否则可能烧毁 IO。接线前用万用表/规格书确认，不要凭外观猜。
- **排针引脚号**：底板丝印与原理图为准。**不要凭记忆接线**——用本文第 4 节的 `--loopback` 模式先验证「这两个针脚确实是 UART3 的 TX/RX」。

### 2.2 上电顺序（手册警告）

《FM22x 用户开发手册 V1.7》明确：**模组未上电时，若 UART 已连外部设备，外部设备 UART 须保持低电平**。
即：先给模组供电，再让上位机串口进入工作状态；或保证上位机侧在模组上电前不驱动 TX。

### 2.3 I2C（DS3231，到货后）

1. 先探测：`i2cdetect -y 0` / `i2cdetect -y 1`，确认 **0x68** 有响应（DS3231 固定地址）。
2. 若内核未启用 `ds1307` 驱动，需要在设备树里挂节点并重新烧录 DTB，形如（**总线号以原理图为准**）：
   ```dts
   &i2c1 {
       ds3231: rtc@68 {
           compatible = "maxim,ds3231";
           reg = <0x68>;
       };
   };
   ```
3. 成功后内核导出 **`/dev/rtc1`**（`rtc0` 仍是 SNVS，不用它）。
4. 首次写入时间：在 **app 停止**时执行 `hwclock -f /dev/rtc1 -w`（app 运行期间 `/dev/rtcN` 被本工程独占持有，见第 6 节）。

## 3. 软件配置项

| 环境变量 | 含义 | 默认值 | 上板应设置 |
|---|---|---|---|
| `SAFE_FACE_BACKEND` | 人脸后端 | 构建期默认（`fake`） | `fm225` |
| `SAFE_FM225_DEV` | FM225 串口节点（**新增，优先**） | 无 | `/dev/ttymxc2` |
| `SAFE_FACE_DEV` | 旧的串口节点名（**兼容保留，次优先**） | 无 | 可不设 |
| `SAFE_TIME_BACKEND` | 时间后端 `sys` / `rtc` | `sys` | `rtc`（DS3231 挂好后） |
| `SAFE_RTC_DEV` | RTC 设备节点 | `/dev/rtc1` | `/dev/rtc1` |

优先级：`SAFE_FM225_DEV` > `SAFE_FACE_DEV` > `/tmp/fm225_host`（PC 侧 socat 虚拟串口，与 `tools/fm225_sim.py` 联调用）。
代码位置：`app/hal/face/backend_fm225.c` 的 `fm225_open()`；波特率固定 **115200 8N1 无流控**（手册 §五(一)），与 `tools/fm225_selftest.py` 的配置一致。

### 3.1 板上持久化位置

`SAFE_FACE_BACKEND` / `SAFE_FM225_DEV` / `SAFE_TIME_BACKEND` 写在启动包装脚本
**`/usr/share/lvgl/run_lvglsim.sh`**（`/etc/init.d/S05lvgl` 拉起的就是它），
在 `cd /usr/share/lvgl` 之前加：

```sh
export SAFE_FACE_BACKEND=fm225
export SAFE_FM225_DEV=/dev/ttymxc2
# DS3231 挂好并确认 /dev/rtc1 存在后再开：
# export SAFE_TIME_BACKEND=rtc
# export SAFE_RTC_DEV=/dev/rtc1
```

改完 `/etc/init.d/S05lvgl restart`，日志看 `/var/log/lvglsim.log`。

### 3.2 启动成功的判据（日志关键字）

```
[time] 后端 = rtc（/dev/rtc1，外部 RTC，断电保持）   # 或 sys（未开 RTC 时）
[fm225] 已打开 /dev/ttymxc2（fd=N，115200 8N1）
[app] safe 1.0.0  platform=fbdev  face=fm225  data=/var/lib/safe
```
若串口没打开，会看到
`[fm225] open <节点> 失败：No such file or directory` + `[fm225] 串口未就绪，start 时重试打开`——
**这是既有降级行为（不阻塞启动）**，按第 5 节排查。

## 4. 自检工具 `tools/fm225_selftest.py`

**纯 Python 标准库**（`os` / `termios` / `select`），**不依赖 pyserial**——板子（Buildroot，Python 3.8.5）可直接跑。

### 4.1 用法

```sh
# 板上（adb shell / 串口终端里）
python3 fm225_selftest.py /dev/ttymxc2                 # 监听模式：等模组主动上报
python3 fm225_selftest.py /dev/ttymxc2 --send-reset    # 先下发 FACE_RESET 再监听
python3 fm225_selftest.py /dev/ttymxc2 --loopback      # 回环：TX/RX 短接，验引脚与波特率
python3 fm225_selftest.py /dev/ttymxc2 --timeout 15 --baud 115200
```

不传节点时，按 `SAFE_FM225_DEV` > `SAFE_FACE_DEV` > `/tmp/fm225_host` 取默认（与主程序同一套优先级）。

### 4.2 三种模式怎么选

| 模式 | 何时用 | 判据 |
|---|---|---|
| `--loopback` | **到货后第一步**：短接排针 TX-RX，模组可不上电 | 收发的 6 字节完全一致 → 节点/引脚/波特率三者都对 |
| 监听（默认） | 模组已上电，想知道链路是否通 | 收到任意 XOR 校验正确的帧（上电就绪是 `NOTE READY`：`EF AA 01 00 01 00 00`） |
| `--send-reset` | 监听拿不到反馈时 | 下发 `FACE_RESET`（`EF AA 10 00 00 10`）逼模组回话 |

> `--loopback` 短接前先确认模组 TX 处于高阻/未上电，避免两个输出口对顶。

### 4.3 退出码

| 码 | 含义 | 下一步 |
|---|---|---|
| 0 | PASS：收到合法帧 / 回环字节一致 | 可以起主程序 |
| 1 | NO_DATA：超时一个字节都没有 | 查：模组上电 → TX/RX 是否交叉 → 共地 → 波特率；或先用 `--loopback` 验引脚 |
| 2 | OPEN_FAIL：节点不存在/无权限/被占用 | 查节点是否存在、是否在 `dialout` 组、是否被别的进程占用 |
| 3 | LOOPBACK_BAD：回环收到字节但不一致 | 波特率不对，或短接的不是这个节点 |
| 4 | BAD_FRAME：有字节但无一帧 XOR 校验通过 | 波特率大概率不对 |

### 4.4 已验证（VM + 板上）

- VM（PTY 对）：回环 0 / NOTE READY 监听 0 / 坏帧 4 / 无数据 1 / 节点不存在 2 —— 五种路径全部符合设计。
- **板上**：`/dev/ttymxc2` 监听 → 节点存在、打开成功、termios 配置成功、0 字节（`rc=1`，因为模组未到货）；
  `/dev/ttymxc9` → `rc=2`；`--loopback`（未短接）→ `rc=1`；`--help` 正常。

## 5. 故障排查表

| 现象 | 原因（按概率） | 处理 |
|---|---|---|
| `[fm225] open ... 失败：No such file or directory` | 节点名写错 / 内核没导出 | `ls /dev/ttymxc*`；确认 `SAFE_FM225_DEV` |
| 自检 `rc=1`（一个字节都没有） | ① 模组没上电 ② TX/RX 没交叉 ③ 没共地 ④ 波特率 | 按 4.3 顺序排查；先做 `--loopback` |
| 自检 `rc=4`（有字节但校验全错） | 波特率不对 | 试 `--baud 9600`（部分模组出厂默认不同），以手册为准 |
| 自检 `rc=3`（回环字节不一致） | 短接的不是这个节点 / 波特率 | 换节点重试 |
| 主程序报 `fm225 命令 0x12 无应答（重发 3 次）` | 链路单向（只发不收）或模组忙 | 先跑自检确认双向；确认模组已进 STANDBY |
| app 起不来，日志停在 `[fm225]` | 不会——串口失败是降级路径，不阻塞启动 | 看 `[app] safe ...` 那行是否出现 |

## 6. 已知坑

1. **`/dev/rtcN` 是独占设备（板上实测）**：rtc-dev 用 `RTC_DEV_BUSY` 位做互斥，同一时刻只允许一个进程打开，
   且被异常占用的进程退出后该位**可能不复原**（实测：一个卡在 `read()` 的调试 `dd` 被 kill 后，
   连续 5 次 `open` 仍全部 `EBUSY`）。
   → 因此本工程的 RTC 后端**首次成功后常驻 fd 复用**，不做「每次读都开关」。
   → 代价：app 运行期间 `hwclock` 访问同一节点会得到 `EBUSY`。**校时请走 `hal_time_set`（RPC `sync_time`），
   或在 app 停止后用 `hwclock -f /dev/rtc1 -w`。**
   → **千万不要对 `/dev/rtcN` 执行 `dd` / `cat` / `head`**：rtc-dev 的 `read()` 会等 RTC 中断，会**永久挂住**并把设备占死。
2. **`/dev/rtc0` 不要用**：它是片上 SNVS，无备份电池，上电归零（见第 1 节）。DS3231 是 `/dev/rtc1`。
3. **模组未上电时的 UART 电平**：见 2.2，上电顺序错了有损坏风险。
4. **`SAFE_TIME_BACKEND=rtc` 但 DS3231 没挂**：会打一条 `[time] 请求 rtc 后端，但 /dev/rtc1 不可用 …
   降级 sys` 并继续正常启动——**这是设计内的优雅降级**，不是故障。
